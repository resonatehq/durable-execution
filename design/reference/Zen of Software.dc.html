The Zen of Software

A state, an action, an answer — and what each definition after them makes impossible.

6 min read · Sept 5, 2026

A system is not its code. Fix three types — what a state is, what can be asked of it, what it answers — and a moment records all three.

StateAction Lean 4 
axiom State  : Type
axiom Action : Type
axiom Output : Type

structure StateAction where
  state  : State
  action : Action
  output : Output

abbrev Trace := Nat → StateAction

A trace alone is just a list; what makes one real is a place to begin and a total rule that turns a state and an action into the next state and an answer.

Next, Valid Lean 4 
abbrev Next := State → Action → State × Output

def Valid (init : State) (next : Next)
    (trace : Trace) : Prop :=
  (trace 0).state = init
  ∧ ∀ t : Nat,
      next (trace t).state (trace t).action
        = ((trace (t + 1)).state, (trace t).output)

Put init and next in one place and the object gets a name; a machine does not describe behavior, it generates it.

Machine, Runs Lean 4 
structure Machine where
  init : State
  next : Next

def Runs (m : Machine) (tr : Trace) : Prop :=
  Valid m.init m.next tr

But only part of a trace is anyone else’s business. Strip the states — they are ours — and what is left is the observable behavior: what was asked, and what came back.

Behavior, Abstracts Lean 4 
abbrev Behavior := Nat → Action × Output

def observe (tr : Trace) : Behavior :=
  fun t => ((tr t).action, (tr t).output)

def Abstracts (spec impl : Machine) : Prop :=
  ∀ tr, Runs impl tr →
    ∃ tr', Runs spec tr' ∧ observe tr' = observe tr

No abstraction function anywhere in that. A specification and an implementation are not different kinds of document — they are two machines, and one stands for the other when nothing you can ask will tell them apart.

It is still a claim about infinitely many traces, so in practice you exhibit an abstraction function and prove a single commuting square.

Abs, Refines Lean 4 
abbrev Abs := State → State

def Refines (spec impl : Machine) (abs : Abs) : Prop :=
  abs impl.init = spec.init
  ∧ ∀ s a,
      (abs (impl.next s a).1, (impl.next s a).2)
        = spec.next (abs s) a

Refines implies Abstracts, and not the other way round — which is the honest shape of every proof technique. Both are reflexive and transitive, so machines are ordered: specification is not a kind of artifact but a position, and the same object specifies what implements it and implements what specifies it.

Proving that is expensive, so mostly we sample it — and sampling needs one more judgement, because the rule answers every action, including the absurd ones, while which actions should be asked is ours to decide.

Legal, Broken Lean 4 
abbrev Legal := State → Action → Bool

/-- Does the trace break in its first `n` steps? -/
def Broken [BEq State] [BEq Output]
    (init : State) (next : Next) (legal : Legal)
    (trace : Trace) (n : Nat) : Bool :=
  !((trace 0).state == init)
  || (List.range n).any fun t =>
       legal (trace t).state (trace t).action
       && !(next (trace t).state (trace t).action
              == ((trace (t + 1)).state, (trace t).output))

So a test is not a function or a fixture: it is a list of actions you feed in, and a trace is what comes out.

Test, run Lean 4 
abbrev Test := List Action

def run (init : State) (next : Next) (test : Test) :
    List StateAction :=
  (test.foldl
    (fun (acc, s) a =>
      let (s', o) := next s a
      (acc ++ [{ state := s, action := a, output := o }], s'))
    ([], init)).1

Which lets us ask the only real question about a suite — if every test in it passes, do we know the system is right?

Complete Lean 4 
abbrev Sut := Test → List StateAction

variable (sut : Sut)
variable (init : State) (next : Next)

def Passes (test : Test) : Prop :=
  sut test = run init next test

def Complete (suite : List Test) : Prop :=
  (∀ t ∈ suite, Passes sut init next t) →
    ∀ t, Passes sut init next t

Which is the same relation as before, narrowed to a finite list. Passes compares one behavior; Abstracts compares all of them at once. Sampled or proved.
